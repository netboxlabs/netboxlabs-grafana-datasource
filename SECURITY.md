# Security Policy

## Supported versions

Security fixes are released as new versions of the plugin. Please keep the plugin updated to the latest release.

## Reporting a suspected vulnerability

Please do not report security issues in public GitHub issues, discussions or pull requests.

Report them privately, either way:

* Through GitHub: on the repository's **Security** tab, choose **Report a vulnerability**.
* By email to `security@netboxlabs.com`.

To help us triage, please include:

* The plugin version, Grafana version and NetBox version
* Steps to reproduce, with the data source configuration involved (never include a real API token)
* What an attacker could do, and which Grafana role they would need

We do not accept reports generated by automated tooling that only suggest a file or dependency _may_ be vulnerable without a demonstrated impact on this plugin.

## What happens next

A member of the NetBox Labs security team will review your report and follow up as the investigation progresses. We coordinate disclosure with the reporter, and fixes are published as a new release together with a GitHub security advisory.

As this plugin is free open source software, we do not offer monetary compensation for reports; your contributions are greatly appreciated.

## Securing your deployment

The plugin queries NetBox with the API token configured on the data source. Anyone who can query the data source in Grafana can read whatever that token can read, so:

* Use a token for a dedicated NetBox user with view-only permissions, limited to the object types your dashboards need
* Leave **Skip TLS verify** off, and reach NetBox over HTTPS
* Where available (Grafana Enterprise and Grafana Cloud), restrict who can query the data source with data source permissions
