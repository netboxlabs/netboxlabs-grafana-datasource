# Grafana provisioning (shared by the dev and demo stacks)

Mounted at `/etc/grafana/provisioning` by both the root dev compose and the
[demo stack](../demo). One set of files serves both:

| Dir | What | Notes |
| --- | --- | --- |
| `datasources/` | NetBox (uid `netboxlabs-netbox`, url/token from `${NETBOX_URL}`/`${NETBOX_API_TOKEN}`), Prometheus (uid `prometheus`), Loki (uid `loki`) | Prometheus/Loki point at the demo compose service names; in the plain dev stack they're present but dormant. |
| `dashboards/` | File provider + `netbox-demo.json`, the **NetBox Enrichment Demo** dashboard (generated by `demo/mkdash2.py --emit-provisioned`) | Regenerate after editing the panel model; don't hand-edit the JSON. |
| `alerting/` | `netbox-object-count.yml`, a Grafana-managed alert rule backed by a NetBox count query; `netbox-alert-enriched.yml`, a Grafana-managed alert rule using alertTable mode, one alert instance per offline device, carrying NetBox context (site/role/tenant) as labels; `netbox-device-info.yml`, a Grafana-managed **recording** rule that writes NetBox's device inventory into Prometheus as `netbox_device_info` for PromQL joins | The alert rules work in both stacks (same datasource uid). The recording rule needs the demo's Prometheus (remote-write receiver on, data source typed as Prometheus) and sits in Error in the plain dev stack. |

The importable (share-anywhere) variant of the dashboard lives at
[`demo/netbox-demo-dashboard.json`](../demo/netbox-demo-dashboard.json). Use
Grafana → Dashboards → Import.

More: [Provision dashboards and data sources](https://grafana.com/tutorials/provision-dashboards-and-data-sources/)
